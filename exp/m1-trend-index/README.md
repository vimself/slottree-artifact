**问题**：单类型 Kleene 模式的趋势聚合 `RETURN g, AGG PATTERN E+ SEMANTICS skip-till-any-match WHERE [g] AND E.a ⋈ NEXT(E).a WITHIN W SLIDE s`，⋈ ∈ {>, <}（严格），AGG ∈ {COUNT(*), SUM(E.a)}。语义同 T20 判据（`exp/t20-trend-headroom/README.md` 第 1 节）：窗口 j 覆盖 [j·s, j·s + W)，时间以数据最早时间为 0；每个窗口、每个组，所有「组内按时间递增、相邻两个事件满足 ⋈」的事件序列：COUNT 数序列个数，SUM 把每条序列里各事件的 a 相加再求总和（GRETA 定义 2、Cogra §2.3）。算术统一取模 2⁶⁴（无符号 64 位回绕），属性 a 取整数（分 / 次每分钟 / 秒）；所有臂同一口径。

**臂**：
- **OPP**：C++ 复现 GRETA 运行时（PVLDB'17 §7–8；单类型 Kleene + 相邻谓词时 Cogra SIGMOD'19 的混合粒度聚合器退化为它，Cogra §5 Alg. 2 第 10–11 行）：按窗格（= 滑动步长 s）分段，每个窗格一棵按 a 有序的顶点树，新事件在覆盖它的各窗格树上做范围查找，对每个合格前驱 p、对 p 与 e 的每个共同窗口累加一次；窗格在它所属的最后一个窗口关闭后整体删除。

## 2. 协议要点（实现规格，给 实现段）

### 2.1 口径

- 事件 (g, t, a)：组、时间（整数微秒）、整数属性。窗格 π(e) = ⌊t / s⌋；窗口 j 覆盖窗格 j … j + k − 1，k = W / s（本实验里 W 都被 s 整除：WPI k ∈ {30, 60, 180}，PAMAP2 {10, 20, 60}，Nasdaq / 公交 {1, 2, 6}）。事件 e 属于窗口 J(e) = [π(e) − k + 1, π(e)]；先到的 p 与 e 的共同窗口是 [π(e) − k + 1, π(p)]
- 流按全局时间处理（各组交错），每组各自一套结构（GRETA §6 的分组 = 划分子流）。窗口 j 在窗格 j + k − 1 结束时关闭：新事件的窗格 π 到来时，先关闭所有 j ≤ π − k 且未输出的窗口（含空窗格的跨越），把 final[j] 写进每组一个的输出数组（计时区内不做 I/O；结束后打印全部输出的校验和，各臂必须一致）
- COUNT 与 SUM 的递推（GRETA Thm 2、Cogra 附录 C 表 9）：c_j(e) = 1 + Σ_{p 合格, p 在窗口 j} c_j(p)；sum_j(e) = a_e · c_j(e) + Σ_p sum_j(p)；final_j += c_j(e)（COUNT）或 sum_j(e)（SUM）。E 既是 START 也是 END 类型。两种聚合各跑一遍（各一行），不合并
- 数据来源：`exp/t20-trend-headroom/data/{wpi,pamap2,nasdaq,bus}.tsv`（被忽略、本机已有）。`prep_m1.py` 读它们，把属性转成整数（WPI 价格 × 100 取整、PAMAP2 心率取整、Nasdaq 收盘价 × 100 取整、公交延误取整），时间转整数微秒，按开发 / 留出切成 `data/<名>_{dev,hold}.tsv`（Nasdaq、公交只有 hold）；不改顺序

### 2.2 OPP：GRETA 运行时的忠实复现（要点逐条对原文）

1. 每组、每个窗格一棵顶点树（GRETA §7「Vertex Tree」：按谓词属性排序、支持范围查找；用 `std::multimap<int64, Vertex*>` 或 B 树，谁快用谁——对手取有利的实现）；窗格数组按时间递增
2. 顶点存 a、π、两个长 k 的数组 cnt[]、sum[]，按窗口号模 k 定位（原文是每顶点一个窗口哈希表，给它换成密集数组是对它有利的改造，README 里写明）
3. 新事件 e：对每个存在的窗格 π' ∈ [π(e) − k + 1, π(e)]，在它的树上做一次范围查找（⋈ 为 > 取 a > a_e 的区间，< 取 a < a_e），**逐个**遍历返回的前驱 p，对每个共同窗口 j ∈ [π(e) − k + 1, π'] 做 cnt_j(e) += cnt_j(p)、sum_j(e) += sum_j(p)（GRETA §8 Thm 4 证明：「found in O(log_b m + m) time by a range query」，再「a predecessor event of e updates at most k aggregates of e」）；然后对 j ∈ J(e)：cnt_j += 1，sum_j += a_e · cnt_j，final_j += cnt_j 或 sum_j；把 e 插进窗格 π(e) 的树
4. 窗格 π' 在窗口 π' 关闭后整体删除（§7「a whole pane with its associated data structures is deleted after the pane has contributed to all windows to which it belongs」）
5. 要对的量级（忠实性）：Cogra 附录 D.2 报有谓词、选择度 90%、每窗 5 万事件时 Cogra 对 GRETA 只快 2×；GRETA Fig. 11 在 Linear Road 每窗 1 万事件、选择度 50% 下延迟稳定。本机只能对「随每窗事件数二次增长、随选择度线性增长」这两条形状（跑一条合成流，每窗事件数 {1k, 2k, 5k, 10k, 20k}，报在 `report_m1.txt` 描述性一节），没有原机器的绝对数可对。Gloria 仓库里 Hamlet 的 Java 前驱扫描（`<internal>`，线性扫 + `indexOf`）比 GRETA 原文弱，不作对手

### 2.3 M：窗口槽聚合树（方法；细节与改造对应关系见 `<internal>` 第 4 节）

每组一棵按 (a, 到达序) 为键的平衡搜索树（实现用 treap；键唯一所以重复属性值靠到达序区分）。每个结点存：
- 自己的 own[k]：槽 i 存 {wid, cnt, sum}，wid 是窗口号，槽号 = wid mod k；只有 wid ∈ J(e) 的 k 个槽有值
- 子树聚合 sub[k]：槽 i 存 {wid, cnt, sum} = 子树里所有结点在窗口 wid 上的 own 之和；**读时 wid 不等于所问窗口就视为 0**（这就是「按窗口槽整体过期」：窗口关闭后它的槽自动失效，槽号被 k 个窗格之后的窗口重用，不删任何东西）

新事件 e（窗格 π，J = [π − k + 1, π]）：
1. **一次下降**：按 ⋈ 求「键在 e 之前 / 之后」的所有结点在 J 上的聚合：从根出发，⋈ 为 < 时若 a_e > 键则累加左子树 sub 与结点 own 的 J 槽后向右，否则向左（> 镜像）；得到 acc_j（cnt、sum），j ∈ J
2. c_j(e) = 1 + acc_cnt_j；sum_j(e) = a_e · c_j(e) + acc_sum_j；final_j += c_j(e) 或 sum_j(e)
3. **一次插入**：按 treap 规则插入新结点（own = 上面的 k 个槽），沿插入路径自底向上把 J 槽加进祖先的 sub（槽里 wid ≠ j 就先清零再写 j）；旋转过的结点按「own + 左 sub + 右 sub」只重算 J 槽
4. 结点在 π_node ≤ π − k 后是死结点（它所有窗口都已关闭，对活槽没有贡献）。**压缩**：每组死结点数 > 活结点数时，中序遍历取活结点、线性时间建平衡树、按 own 重算 sub（只算活窗口的槽）。摊还每事件 O(k)；内存 ≤ 2 × 活结点。（变体：每窗格结束时逐个删死结点，O(k log n) 每个；两种都实现时在第 3 节记一行，正文用快的）

每事件 O(k log n_live)（下降与插入各碰 O(log n) 个结点、每个结点 k 个槽）+ 摊还 O(k)；内存 O(n_live · k)。与 OPP 的差别只在两处：前驱的和由子树聚合给出而不逐个加；过期靠槽号重用而不删。

**按组规模切换**（第 4 处改造）：每组有两种模式——索引（上面的树）与扫描（2.2 的 OPP 结构，代码共用）。每个窗格边界看该组活事件数 n_live：扫描模式且 n_live ≥ τ_high ⇒ 从活事件建树切到索引；索引模式且 n_live < τ_low ⇒ 切回扫描（树丢掉，按窗格重建 OPP 结构）；τ_high = 2 τ_low 做滞回。**τ_low 只用开发集定**：在 {16, 32, 64, 128, 256} 里取开发集 12 行总时间最小的，定下后写进第 3 节，留出集不再动

### 2.4 消融臂

- **A1**：每个活跃窗口各一棵 treap（结点只存一对 cnt、sum），事件插进它所属的 k 棵树，查询做 k 次下降；窗口关闭时整棵树丢掉。这是审稿人一眼会想到的「每个窗口一棵聚合索引」；它和 M 的差别就是第 1 处改造（一次下降读 k 个连续槽 vs k 次下降；一棵树 vs k 棵）。**A1 比 M 快就说明第 1 处改造不成立**：论文的多窗口方案改用 A1，并在第 3 节写明偏离——这是设计选择，不是判据
- **A4**：M 去掉切换（所有组始终用索引）。它与 M 的差别是第 4 处改造；低频数据上 A4 若已满足 K2，第 4 处改造的贡献就是零，论文照实写

- OPP 顶点的窗口聚合是密集数组，按「相对本顶点第一个窗口的偏移」存，使 p 与 e 的共同窗口在两边都是连续的一段（原文是每顶点一个窗口哈希表）
- 窗口输出与窗格删除按组惰性做：组 g 的下一个事件进到新窗格时删 π′ ≤ π − k 的窗格；窗口在它的槽被 k 个窗格之后的窗口重用时、或流结束时输出。输出内容与「窗格结束时统一关闭」相同，计时都在区内
- M 的结点：own 按偏移存（同 OPP），sub 按窗口号 mod k 存、带窗口号标签。⋈ 为 > 时同值的新结点放右、为 < 时放左，使插入路径与查询下降路径重合 ⇒ 下降时记下路径，插入沿它更新 sub，再按 treap 优先级向上旋转（旋上来的结点照搬父结点的 sub，父结点由 own + 孩子重算 k 个槽）。优先级是每组固定种子的 xorshift32
- 死结点只实现了「压缩」（死 > 活时中序取活结点、按原优先级线性时间建笛卡尔树、后序重算 sub），没实现「逐个删」变体（第 2.3 节第 4 条）
- 切换：扫描 → 索引时把活顶点按键排序、线性建树；索引 → 扫描时中序取活结点、按到达序放回各窗格的顶点树；与 OPP 共用同一份扫描代码
- 每次重复前新建空结构（不计时），计时包住全流处理与最后一批窗口输出；结构的释放不计时
- 闸：(a) 300 条合成流 × 9 个臂配置（OPP 两种顶点树、A1、A4、M 的 τ_low ∈ {1, 2, 3, 8, 64}，τ 小的配置每条流都会切换、压缩）× COUNT / SUM = 5,400 项，错误 0；(b) 6 份切分 × 每组前 2,000 个事件 × 6 个查询 × 6 个臂配置 = 216 次，与 OPP 逐窗口相等
